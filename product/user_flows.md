# User Flows

The frozen set has 31 flows: 12 normal flows and 19 exception flows. Local setup checks time, configures, reviews, persists and inspects the active plan. Scheduled execution produces attempt evidence, not automatic success. Status review inspects evidence and freshness first.

Remote editing separates Draft, Change sent, Waiting for device confirmation, Device confirmed and Could not confirm. A matching request/version acknowledgement proves configuration, not food output. Offline views show last sync and cached labels, disable remote controls and condition local continuation on valid power/time/configuration. Reconnection proves no meal outcome. Maintenance pauses, cleans/refills, reassembles, checks and explicitly resumes. Near-meal manual feeding and missed-meal catch-up remain unresolved, without invented retry policies.

Eight App screens plus one simplified local concept use grayscale low fidelity and optional App access. Prototype flow A (remote edit) runs Home→Schedule→Edit→Review→Send→Pending→matching device acknowledgement. Flow B (offline) shows offline/cached/last-sync information, conditional local continuation and reconnect. Flow C (uncertain delivery) moves from an attempt to Delivery unconfirmed, known/unknown explanation and safe checking, without automatic retry.

SVG and HTML assets copy the frozen low-fidelity wireframes rather than redesign them. Fixture controls drive demonstration conditions, not hardware capabilities. No native Figma, industrial interface or usability test exists. Selected screens are shown on the live website.
