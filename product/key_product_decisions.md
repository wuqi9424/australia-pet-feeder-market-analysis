# Key Product Decisions

Five decisions use problem→choice→trade-off→validation. Local-first prevents unavailable remote services from removing valid local execution authority; firmware/storage/control complexity requires interruption testing. Optional connectivity retains convenience without a core dependency; dual-surface synchronisation requires value and acknowledgement-comprehension tests. Truthful status refuses motor→food→consumption inference; uncertainty requires comprehension and output testing. Excluding camera/audio focuses routine feeding at the cost of monitoring use cases, requiring user trade-off tests. Recovery in MVP addresses missed/duplicate/unknown outcomes after interruption, adding state/test complexity that requires fault injection.

These are design choices, not validated designs mechanically derived from review frequencies.
